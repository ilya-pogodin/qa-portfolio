# POST /payments — создание платежа

Объект: ZooTicket Payments API v1.1.0
Метод: `POST /payments`
Спецификация: [openapi.yaml](https://github.com/ilya-pogodin/data-analytics-portfolio/blob/main/systems-analysis/zooticket/openapi.yaml)
Дата: 22.09.2026

Обязательные поля тела: `orderId`, `amount`, `currency`, `returnUrl`.
Обязательный заголовок: `Idempotency-Key`.
Авторизация: Bearer (JWT).

Техники: эквивалентное разбиение, граничные значения, таблица решений для идемпотентности.

## Заметки

TC-PAY-03 намеренно оставлен незакрытым. Стандартное поведение платёжных API в такой ситуации — вернуть 422 с указанием, что ключ уже использован с другими параметрами. В текущей версии спецификации этого нет, поэтому ожидаемый результат зафиксировать нельзя. Выяснить у аналитика.

Граничные значения по `amount` полноценно не разложены: в спецификации нет ни минимума, ни максимума. После того как ограничения появятся, добавить кейсы на min−1, min, max, max+1.
