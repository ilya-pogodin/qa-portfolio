# POST /payments/{id}/refund — возврат платежа

Объект: ZooTicket Payments API v1.1.0
Спецификация: [openapi.yaml](https://github.com/ilya-pogodin/data-analytics-portfolio/blob/main/systems-analysis/zooticket/openapi.yaml)
Дата: 22.09.2026

Тело запроса: `amount` (обязательное).
Коды ответов по спецификации: 200, 400, 401, 404, 422, 500.

|---|---|---|---|---|---|

## Заметки

Два кейса (TC-REF-05 и TC-REF-06) упираются в одну и ту же дыру: в спецификации не описаны правила частичного и повторного возврата. Пока правила не появятся, ожидаемый результат — предположение, а не требование. Отмечено в дефектах.

Связка с состояниями билета: после успешного возврата билет должен перейти в состояние «возвращён». Проверка перехода вынесена в отдельный набор — [TC-ticket-lifecycle.md](TC-ticket-lifecycle.md).
