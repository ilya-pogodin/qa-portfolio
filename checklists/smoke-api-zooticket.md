# Smoke-чек-лист: ZooTicket Payments API

Когда применять: после выкатки новой сборки на тестовый стенд, до начала основного прогона.
Цель: за 10–15 минут понять, есть ли смысл тестировать дальше.
Версия API: v1.1.0

---

## Доступность

- [ ] Базовый адрес отвечает, сервис поднят
- [ ] Swagger-страница открывается и соответствует версии сборки
- [ ] Запрос без токена возвращает 401, а не 500

## Создание платежа

- [ ] POST /payments с валидными данными возвращает 201
- [ ] В ответе присутствуют `id`, `status`, `paymentUrl`
- [ ] `paymentUrl` открывается в браузере
- [ ] Повторный запрос с тем же `Idempotency-Key` не создаёт второй платёж
- [ ] Запрос с пустым телом возвращает 400, а не 500

## Статус платежа

- [ ] GET /payments/{id} по существующему платежу возвращает 200
- [ ] Статус в ответе совпадает с реальным состоянием платежа
- [ ] GET по несуществующему id возвращает 404

## Возврат

- [ ] POST /payments/{id}/refund по оплаченному платежу возвращает 200
- [ ] Статус платежа после возврата меняется на `refunded`
- [ ] Возврат по неоплаченному платежу возвращает 422, а не 500

## Webhook

- [ ] Уведомление с валидной подписью принимается, код 200
- [ ] Уведомление с неверной подписью отклоняется, код 400
- [ ] Статус платежа после уведомления обновляется

## Общее

- [ ] Ни один из проверенных сценариев не завершился кодом 5xx
- [ ] Ошибки приходят в формате `{code, message}`, а не в виде HTML или стектрейса
- [ ] В логах нет необработанных исключений по проверенным запросам

---

Если провален любой пункт из разделов «Доступность» или «Создание платежа» — сборка не принимается, дальнейшее тестирование останавливается.
