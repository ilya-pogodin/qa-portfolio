# Чек-лист: покупка билета через сайт

Объект: прототип покупки билета ZooTicket, 4 экрана (выбор → данные → оплата → подтверждение).
Основа: прототип и требования из [systems-analysis/zooticket](https://github.com/ilya-pogodin/data-analytics-portfolio/tree/main/systems-analysis/zooticket)

---

## Экран 1. Выбор билета

- [ ] Отображаются все типы билетов с ценами
- [ ] Выбор даты посещения доступен, прошедшие даты недоступны
- [ ] Количество билетов изменяется кнопками и вводом с клавиатуры
- [ ] Нельзя выбрать ноль или отрицательное количество
- [ ] Итоговая сумма пересчитывается при изменении количества
- [ ] Кнопка «Далее» неактивна, пока билет не выбран

## Экран 2. Данные покупателя

- [ ] Обязательные поля помечены визуально
- [ ] Email проверяется на формат, сообщение об ошибке понятное
- [ ] Телефон принимает разные форматы ввода или маскируется
- [ ] Попытка отправить пустую форму показывает ошибки, а не отправляет данные
- [ ] Данные сохраняются при возврате на предыдущий экран
- [ ] Поля не теряют содержимое при обновлении страницы

## Экран 3. Оплата

- [ ] Сумма и состав заказа совпадают с выбранными на экране 1
- [ ] Переход на платёжную страницу работает
- [ ] Повторное нажатие кнопки «Оплатить» не создаёт второй платёж
- [ ] Отмена оплаты возвращает на сайт с понятным сообщением
- [ ] Закрытие вкладки во время оплаты не оставляет заказ в подвешенном состоянии

## Экран 4. Подтверждение

- [ ] Отображается QR-код билета
- [ ] Письмо с билетом приходит на указанный email
- [ ] Данные в письме совпадают с данными на экране
- [ ] Билет доступен по прямой ссылке после закрытия страницы
- [ ] QR-код читается сканером и камерой телефона

## Сквозные проверки

- [ ] Кнопка «Назад» в браузере не ломает шаг оформления
- [ ] Все тексты без опечаток, единый стиль обращения к пользователю
- [ ] Вёрстка не разъезжается на 360 px по ширине
- [ ] Формы заполняются с клавиатуры, порядок табуляции логичен
- [ ] Двойной клик по кнопкам не приводит к дублям
