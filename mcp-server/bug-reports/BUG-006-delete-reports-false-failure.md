# BUG-006 — Инструменты удаления сообщают о неудаче при успешном ответе API

**Краткое описание:** при ответе внешнего API с кодом 204 без тела инструмент удаления возвращает сообщение об ошибке, хотя операция на стороне API выполнена успешно

**Окружение:** macOS, Node.js v24.21.0; внешний API — локальная заглушка на порту 4001
**Severity:** Major
**Priority:** High
**Дата:** 27.09.2026
**Статус:** открыт, воспроизведён и подтверждён прямым запросом к API

---

## Предусловия

Заглушка API запущена, MCP-сервер запущен с `MCP_API_URL=http://localhost:4001`. Товар с идентификатором `p1` существует.

## Шаги воспроизведения

1. Убедиться, что товар существует — запросить его напрямую у API:

```
curl -i http://localhost:4001/products/p1
```

Ответ: `HTTP/1.1 200 OK` с телом товара.

2. Вызвать инструмент удаления через MCP-сервер:

```
curl -X POST http://localhost:4000/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -d '{"jsonrpc":"2.0","method":"tools/call","params":{"name":"delete-product","arguments":{"productId":"p1"}},"id":7}'
```

3. Проверить, что именно ответил API на то же действие:

```
curl -i -X DELETE http://localhost:4001/products/p1
```

## Ожидаемый результат

Инструмент сообщает об успешном удалении — в коде для этого предусмотрен текст «Product deleted successfully».

## Фактический результат

Инструмент возвращает сообщение о неудаче:

```
{"result":{"content":[{"type":"text","text":"Failed to delete product"}]},"jsonrpc":"2.0","id":7}
```

При этом API на шаге 3 отвечает успехом:

```
HTTP/1.1 204 No Content
X-Powered-By: Express
Date: Sun, 27 Sep 2026 13:56:45 GMT
Connection: keep-alive
Keep-Alive: timeout=5
```

Тела в ответе нет — это штатное поведение для кода 204.

Таким образом, на одно и то же действие API сообщает об успехе, а инструмент — о неудаче.

## Примечания

Причина в функции `makeIlyaRequest`. После проверки `if (!response.ok)` выполняется безусловный разбор тела:

```js
return (await response.json()) as T;
```

Код 204 означает «успешно, тела нет». Разбор пустого тела выбрасывает исключение, оно перехватывается блоком `catch`, функция возвращает `null`. Инструмент трактует `null` как отказ и формирует сообщение об ошибке.

Ветка успеха в коде инструмента недостижима: при коде 204 туда попасть невозможно.

Пользователь видит сообщение о неудаче и, скорее всего, повторит операцию — при том, что первая уже прошла.

## Затронутые инструменты

`delete-product` и `delete-order` — оба обрабатывают ответ одинаково.

## Предлагаемая правка

Не разбирать тело, когда его нет. Проверять код ответа перед разбором:

```js
if (response.status === 204) return {} as T;
return (await response.json()) as T;
```

## Ограничение проверки

Проверено на заглушке API, написанной для тестирования. В ней операция удаления отвечает кодом 204, но запись из хранилища не убирает — это упрощение заглушки, а не поведение настоящего API. Для полной проверки нужна реализация, в которой удаление действительно происходит: тогда станет видно и второе следствие — пользователь считает операцию непрошедшей и повторяет её.
