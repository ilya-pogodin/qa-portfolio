# BUG-001 — Не удалось проверить скрипт получения списка возможностей

**Классификация:** неподтверждённое наблюдение, а не подтверждённый дефект MCP-сервера.  
**Окружение исторического прогона:** macOS, Node.js v24.21.0, npm 11.19.0; заявленный SDK — `@modelcontextprotocol/sdk` 1.26.  
**Severity / Priority:** не оцениваются до подтверждения дефекта.  
**Дата заметки:** 27.09.2026  
**Статус:** требуется исходник скрипта.

---

## Что известно

При ручной отправке JSON-RPC-запроса с методом `mcp.list_capabilities` сервер ответил ошибкой `-32601 Method not found`.

Само по себе это ожидаемый ответ: `mcp.list_capabilities` не является стандартным методом MCP. Для получения списка инструментов используется `tools/list`.

Ранее предполагалось, что неподдерживаемый метод вызывает скрипт `get_capabilities.ts`. Но этот файл в текущем репозитории отсутствует, поэтому связь между запросом и скриптом не проверена. Следовательно, сейчас нельзя утверждать, что доказан дефект именно скрипта или сервера.

## Исторический запрос

Выполнялся вручную через `curl` во время прогона, когда MCP-сервер был доступен:

```bash
curl -X POST http://localhost:4000/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","method":"mcp.list_capabilities","params":{},"id":8}'
```

Зафиксированный ответ:

```json
{
  "jsonrpc": "2.0",
  "id": 8,
  "error": {
    "code": -32601,
    "message": "Method not found"
  }
}
```

**Важно:** исходный код MCP-сервера сейчас отсутствует в репозитории, поэтому этот шаг нельзя повторить из чистого клона. Пример сохраняется как запись исторического наблюдения, а не как актуальная пошаговая инструкция.

## Ожидаемый результат

Для ручного вызова неподдерживаемого метода ожидается ошибка `-32601`. Для скрипта `get_capabilities.ts` ожидаемый результат определить нельзя до появления исходника и проверки, какой метод он должен вызывать.

Если цель скрипта — получить список доступных инструментов, он должен использовать `tools/list`.

## Дальнейшие действия

1. Добавить исходник `get_capabilities.ts`, если он по-прежнему является частью проекта.
2. Проверить, какой JSON-RPC-метод он вызывает.
3. Запустить именно этот скрипт и только после этого оформить дефект, если фактическое поведение расходится с назначением.

До выполнения этих действий находку нельзя учитывать как подтверждённый дефект продукта.
