# BUG-005 — Инструменты возвращают недопустимый тип содержимого и отклоняются протоколом

**Краткое описание:** при успешном ответе внешнего API инструмент формирует результат с типом содержимого `json`, которого нет в спецификации MCP; SDK отклоняет такой ответ ошибкой −32602, и вызывающая сторона не получает данных

**Окружение:** macOS, Node.js v24.21.0, npm 11.19.0; `@modelcontextprotocol/sdk` 1.26; внешний API — локальная заглушка на порту 4001
**Severity:** Blocker
**Priority:** High
**Дата:** 27.09.2026
**Статус:** открыт

---

## Предусловия

Запущена заглушка API на порту 4001, MCP-сервер запущен с переменной `MCP_API_URL=http://localhost:4001`. Внешний API отвечает корректно.

## Шаги воспроизведения

1. Запустить заглушку: `node stub-api.js`
2. Запустить сервер: `MCP_API_URL=http://localhost:4001 npm run dev`
3. Запросить существующий товар:

```
curl -X POST http://localhost:4000/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -d '{"jsonrpc":"2.0","method":"tools/call","params":{"name":"get-product","arguments":{"productId":"p1"}},"id":3}'
```

## Ожидаемый результат

В ответе приходят данные товара в допустимом протоколом виде.

## Фактический результат

Возвращается ошибка протокола вместо данных:

```
{"jsonrpc":"2.0","id":3,"error":{"code":-32602,
 "message":"MCP error -32602: Invalid tools/call result: [{ \"code\": \"invalid_union\", ... \"path\": [\"content\", 0] }]"}}
```

Полный текст ошибки содержит перебор пяти допустимых типов содержимого, ни один из которых не подошёл:

| Проверенный тип | Причина несовпадения |
|---|---|
| `text` | ожидалось значение `"text"`, поле `text` отсутствует |
| `image` | ожидалось `"image"`, отсутствуют `data` и `mimeType` |
| `audio` | ожидалось `"audio"`, отсутствуют `data` и `mimeType` |
| `resource_link` | отсутствуют `name` и `uri` |
| `resource` | ожидалось `"resource"`, отсутствует объект `resource` |

Путь ошибки: `content[0]` — первый элемент массива содержимого ответа.

## Примечания

Причина в коде: при успешном ответе API инструмент формирует

```js
content: [{ type: "json", json: productData }]
```

Спецификация MCP допускает только пять типов содержимого — `text`, `image`, `audio`, `resource_link`, `resource`. Типа `json` среди них нет, поэтому валидация ответа не проходит.

**Особенность дефекта: инструмент ломается именно на успешном сценарии.** Пока внешний API недоступен, срабатывает ветка обработки ошибки, которая возвращает `{ type: "text", text: "Failed to..." }` — формально корректный ответ. Дефект проявляется только тогда, когда API отвечает данными.

Это объясняет, почему проблема не заметна при значении `MCP_API_URL` по умолчанию: указанный там домен `https://api.ilya.com` не существует, и все вызовы идут по ветке ошибки.

**Почему не поймано при сборке.** Над каждым из десяти сгенерированных инструментов в коде стоит `// @ts-ignore`, отключающий проверку типов. Без него TypeScript отверг бы `type: "json"` на этапе компиляции.

## Затронутые инструменты

Все, возвращающие данные: `get-products`, `get-product`, `add-product`, `update-product`, `get-orders`, `get-order`, `create-order`, `update-order`. Инструменты удаления возвращают текст и этим дефектом не затронуты, но имеют собственную проблему — см. BUG-006.

## Предлагаемая правка

Заменить в шаблоне генератора тип содержимого на допустимый:

```js
content: [{ type: "text", text: JSON.stringify(productData, null, 2) }]
```

Отдельно — убрать `// @ts-ignore` из генерируемого кода: он скрывает именно такие ошибки.
