# BUG-002 — Причину отказа инструмента невозможно определить по ответу

**Краткое описание:** при любой проблеме с внешним API инструмент возвращает одно и то же обобщённое сообщение; настоящая причина остаётся в логе сервера и до вызывающей стороны не доходит

**Окружение:** macOS, Node.js v24.21.0; внешний API недоступен (соединение отклонено)
**Severity:** Major
**Priority:** High
**Дата:** 27.09.2026
**Статус:** открыт

---

## Шаги воспроизведения

1. Запустить MCP-сервер, не поднимая внешний API
2. Запросить товар с существующим идентификатором:

```
curl -X POST http://localhost:4000/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -d '{"jsonrpc":"2.0","method":"tools/call","params":{"name":"get-product","arguments":{"productId":"p1"}},"id":3}'
```

3. Запросить товар с заведомо несуществующим идентификатором:

```
curl -X POST http://localhost:4000/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -d '{"jsonrpc":"2.0","method":"tools/call","params":{"name":"get-product","arguments":{"productId":"p99"}},"id":4}'
```

4. Сравнить два ответа между собой
5. Посмотреть в окно, где запущен сервер, и сравнить с тем, что видит клиент

## Ожидаемый результат

Сообщение об ошибке позволяет понять причину отказа: недоступен сервис, товар не найден, ошибка на стороне API.

## Фактический результат

Оба запроса вернули дословно одинаковый текст:

```
{"result":{"content":[{"type":"text","text":"Failed to retrieve product data"}]}}
```

При этом в логе сервера настоящая причина видна:

```
Error making Ilya request: [TypeError: fetch failed] {
  [cause]: AggregateError [ECONNREFUSED]:
    code: 'ECONNREFUSED',
}
```

То есть диагностика существует и корректна, но остаётся на сервере. Вызывающей стороне уходит сообщение, из которого ничего не следует.

## Примечания

Причина в коде: функция `makeIlyaRequest` заключает весь запрос в `try/catch`, в блоке `catch` пишет ошибку в консоль и возвращает `null`. Вызывающий инструмент видит только `null` и формирует одинаковый текст независимо от того, что произошло: отказ соединения, код 404, код 500 или неразбираемый ответ.

Для пользователя MCP-клиента это означает, что при любой проблеме он получит одно и то же и не поймёт, чинить ему запрос или ждать восстановления сервиса.

Затрагивает все десять сгенерированных инструментов — механизм обработки ошибок у них общий.

## Предлагаемая правка

Различать случаи в тексте ответа: недоступность сервиса, код ответа 4xx, код 5xx. Как минимум передавать код HTTP-ответа, когда он есть.
