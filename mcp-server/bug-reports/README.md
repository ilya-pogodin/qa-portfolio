# Находки и ограничения проверки MCP-сервера

Баг-репорты и наблюдения, записанные после исторических прогонов MCP-сервера, сгенерированного SwaggerHub по OpenAPI-спецификации. Исходный код тестируемого MCP-сервера сейчас не включён в репозиторий, поэтому повторное воспроизведение требует его восстановления.

| ID | Проблема | Severity | Priority |
|---|---|---|---|
| [BUG-005](BUG-005-invalid-content-type.md) | Инструменты отдают недопустимый тип содержимого и отклоняются протоколом | Blocker | High |
| [BUG-006](BUG-006-delete-reports-false-failure.md) | Удаление сообщает о неудаче при успешном ответе API | Major | High |
| [BUG-002](BUG-002-errors-indistinguishable.md) | Причину отказа инструмента не определить по ответу | Major | High |
| [BUG-001](BUG-001-capabilities-script-broken.md) | Неподдерживаемый метод; исходник вызывающего скрипта отсутствует | Требует подтверждения | — |
| [BUG-004](BUG-004-dependency-vulnerabilities.md) | Предполагаемые уязвимости зависимостей; npm audit не выполнен | Требует расследования | — |
| [BUG-003](BUG-003-echo-no-description.md) | У инструмента `echo` нет описания | Minor | Low |

## Главное по итогам

Результаты ниже относятся к историческим прогонам от 27.09.2026 и не воспроизводятся из текущего checkout без исходного кода MCP-сервера. BUG-001 связан с неподдерживаемым методом, но исходник скрипта не представлен; BUG-004 требует аудита зависимостей и пока не подтверждён. Основной подтверждённый дефект — [BUG-005](BUG-005-invalid-content-type.md). Восемь из десяти сгенерированных инструментов возвращают данные в формате, который протокол не принимает, и клиент получает ошибку вместо результата.

Особенность в том, что **дефект проявляется только на успешном сценарии**. Пока внешний API недоступен, срабатывает ветка обработки ошибки, и ответы формально корректны. Именно поэтому в прогоне 1, выполненном без заглушки, проблема не была видна.

Это же объясняет, почему дефект дожил до пользователя: в сгенерированном проекте адрес API по умолчанию указывает на несуществующий домен, и при запуске «как есть» всё выглядит работающим.

## Что покрыто и что нет

Проверены инструменты по товарам и общие механизмы протокола. Инструменты по заказам, обновление товара и поведение при ошибках 5xx от внешнего API остались непроверенными — перечень в конце [отчёта о прогоне 2](RESULTS-run-02.md).
