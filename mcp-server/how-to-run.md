# Текущее состояние и запуск доступной заглушки

Инструкция описывает только то, что находится в текущем репозитории на ветке `main`.

## Важное ограничение

Исходный код тестируемого MCP-сервера в репозитории отсутствует: нет `package.json` с командой `dev`, каталога `src/` и конфигурации TypeScript. Поэтому запустить MCP-сервер на порту 4000 и повторить проверки, адресованные `http://localhost:4000/mcp`, из текущего клона невозможно.

Исторические результаты за 27.09.2026 сохранены в [bug-reports](bug-reports), однако они не являются инструкцией по воспроизведению на текущем checkout. Чтобы вернуть полную воспроизводимость, нужно добавить оригинальные файлы тестируемого MCP-сервера и его зависимости, затем повторить прогоны и обновить результаты.

## Что можно запустить

В репозитории присутствует только заглушка REST API — [stub-api.js](stub-api.js). Она слушает порт 4001 и не реализует MCP-протокол.

### Требования

- Node.js 18 или выше.
- npm, который поставляется вместе с Node.js.

Проверить версии:

```bash
node -v
npm -v
```

### Запуск заглушки

Из корня репозитория:

```bash
cd mcp-server
npm install
npm run stub
```

Ожидаемое сообщение в терминале:

```text
Заглушка API слушает порт 4001
```

Остановить её можно сочетанием `Ctrl+C`.

Проверить доступность списка товаров во втором терминале:

```bash
curl -i http://localhost:4001/products
```

Для исходного состояния в заглушке ожидается HTTP 200 и массив с товаром `p1`.

## Почему этого недостаточно для повторения баг-репортов

Заглушка имитирует внешний API. Ошибки из [BUG-005](bug-reports/BUG-005-invalid-content-type.md) и [BUG-006](bug-reports/BUG-006-delete-reports-false-failure.md) возникают на стороне MCP-сервера, которого в текущем checkout нет. Запросы к порту 4000 не сработают, пока исходный сервер не будет восстановлен.

Не отправляйте запросы к `localhost:4000/mcp`, ожидая получить результат из одной только заглушки: она слушает другой порт и другой протокол.
