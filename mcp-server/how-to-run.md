# Как запустить и протестировать через терминал

Инструкция для macOS. Рассчитана на то, что с терминалом вы раньше не работали.

---

## Часть 1. Знакомство с терминалом

### Как открыть

Нажмите **Cmd + Пробел** — откроется поиск Spotlight. Наберите `терминал` и нажмите Enter.

Откроется окно с текстом вроде:

```
ilya@MacBook-Air ~ %
```

Это приглашение к вводу. Всё, что слева от знака `%`, — служебная информация: ваше имя пользователя, имя компьютера и текущая папка. Символ `~` означает домашнюю папку.

### Как выполнить команду

Набрать текст после `%` и нажать **Enter**. Команду можно вставить копипастом — **Cmd + V** работает.

Попробуйте прямо сейчас:

```
pwd
```

Терминал ответит полным путём к текущей папке, например `/Users/ilya`. Команда `pwd` расшифровывается как «print working directory» — показать, где я сейчас нахожусь.

### Полезные сочетания клавиш

| Сочетание | Что делает |
|---|---|
| **Cmd + T** | новая вкладка в том же окне |
| **Cmd + N** | новое окно терминала |
| **Ctrl + C** | остановить выполняющуюся программу |
| **Стрелка вверх** | подставить предыдущую команду |
| **Cmd + K** | очистить экран |

**Ctrl + C** понадобится обязательно — именно так останавливают запущенный сервер. Обратите внимание: именно **Ctrl**, а не Cmd.

## Часть 2. Подготовка

### Шаг 1. Проверить Node.js

Выполните:

```
node -v
```

**Если ответ вида `v22.1.0`** — Node установлен, версия подходит. Нужна 18 или выше, первое число после `v` должно быть не меньше 18.

**Если ответ `command not found: node`** — Node не установлен.

Откройте **браузер** (не терминал) и перейдите на сайт `nodejs.org`. Скачайте версию с пометкой **LTS**, установите как обычную программу — двойной клик по скачанному файлу, дальше по подсказкам установщика.

После установки закройте окно терминала полностью (**Cmd + Q**) и откройте заново — иначе он не увидит новую программу. Проверьте ещё раз командой `node -v`.

Заодно проверьте npm — он ставится вместе с Node:

```
npm -v
```

### Шаг 2. Перейти в папку проекта

Команда `cd` меняет текущую папку. Набирать длинный путь руками не нужно — есть приём:

1. Наберите в терминале `cd` и **пробел после него**.
2. Откройте Finder, найдите папку с проектом.
3. Перетащите папку мышкой прямо в окно терминала — путь подставится сам.
4. Нажмите Enter.

Проверьте, что попали куда надо:

```
ls
```

Команда `ls` показывает содержимое текущей папки. Должны увидеть `package.json`, `src`, `stub-api.js` и остальные файлы проекта. Файл заглушки `stub-api.js` лежит в проекте изначально, отдельно скачивать его не нужно. Если видите что-то другое — вы не в той папке, повторите шаг.

### Шаг 3. Установить зависимости

```
npm install
```

Команда скачивает библиотеки, от которых зависит проект. Займёт от десяти секунд до минуты, в терминале будет бежать текст. В конце появится строка вроде `added 129 packages`.

Рядом с проектом появится папка `node_modules` — это нормально, там лежат скачанные библиотеки. Трогать её не нужно.

**Если появились строки со словом `warn`** — это предупреждения, а не ошибки, их можно игнорировать. Проблема — только слово `error`.

**Обратите внимание на строку про уязвимости** вида `7 vulnerabilities (1 low, 3 moderate, 3 high)`. Это результат проверки зависимостей на известные проблемы безопасности. Запишите его — для свежесгенерированного проекта это находка. Подробности покажет команда `npm audit`.

## Часть 3. Запуск

Понадобятся три окна терминала: в первых двух будут работать программы, из третьего будете отправлять запросы.

### Шаг 4. Запустить заглушку API

В текущем окне выполните:

```
node stub-api.js
```

Появится строка:

```
Заглушка API слушает порт 4001
```

**Курсор после этого не вернётся, и терминал будет выглядеть зависшим. Так и должно быть** — программа работает и ждёт запросов. Это окно больше не трогаем.

*Зачем нужна заглушка.* Инструменты MCP-сервера обращаются к внешнему API за товарами и заказами. По умолчанию адрес — `https://api.ilya.com`, а такого сайта не существует. Без заглушки любой инструмент будет отвечать ошибкой, и проверить успешный сценарий не получится.

### Шаг 5. Запустить MCP-сервер

Откройте **новое окно** терминала: **Cmd + N**.

Перейдите в ту же папку проекта — тем же способом с перетаскиванием (`cd `, перетащить, Enter).

Выполните:

```
MCP_API_URL=http://localhost:4001 npm run dev
```

Разбор команды: `MCP_API_URL=http://localhost:4001` — это переменная окружения, она говорит серверу, по какому адресу искать API. Мы направляем его на заглушку из шага 4. Дальше через пробел идёт сама команда запуска.

Через 10–20 секунд появится:

```
MCP Stateless Streamable HTTP Server listening on port 4000
```

Выше могут быть строки со словами `ExperimentalWarning` и `DeprecationWarning` — это предупреждения Node, на работу не влияют.

Это окно тоже больше не трогаем.

### Шаг 6. Открыть окно для запросов

**Cmd + N** ещё раз. В это окно переходить в папку проекта не нужно — запросы отправляются по сети.

## Часть 4. Отправка запросов

Запросы отправляются командой `curl` — она есть в macOS изначально, ставить ничего не надо.

### Шаг 7. Первый запрос: список инструментов

Скопируйте и вставьте целиком одной строкой:

```
curl -X POST http://localhost:4000/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -d '{"jsonrpc":"2.0","method":"tools/list","params":{},"id":1}'
```

Разбор команды:

| Часть | Что означает |
|---|---|
| `curl` | программа для отправки запросов |
| `-X POST` | метод запроса |
| `http://localhost:4000/mcp` | адрес; `localhost` — ваш же компьютер |
| `-H "Content-Type: application/json"` | заголовок: отправляем JSON |
| `-H "Accept: ..."` | заголовок: готовы принять JSON или поток событий |
| `-d '{...}'` | тело запроса в одинарных кавычках |

**Одинарные кавычки вокруг тела обязательны.** Внутри тела кавычки двойные. Если перепутать — команда не сработает.

### Как читать ответ

Ответ выглядит так:

```
event: message
data: {"result":{"tools":[...]},"jsonrpc":"2.0","id":1}
```

Это формат Server-Sent Events. Нужное — во второй строке после `data: `. Первая строка служебная.

Ответ придёт одной длинной строкой и читать его будет тяжело. Чтобы разложить по строчкам, добавьте в конец команды ` | python3 -m json.tool` — нет, так не сработает из-за префикса `data:`. Проще скопировать содержимое после `data: ` и вставить в любой онлайн-просмотрщик JSON.

## Часть 5. Проверки

Ниже — команды для основных проверок. Каждую вставлять одной строкой в третье окно.

### Проверка 1. Инструмент echo

```
curl -X POST http://localhost:4000/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -d '{"jsonrpc":"2.0","method":"tools/call","params":{"name":"echo","arguments":{"message":"проверка"}},"id":1}'
```

Ожидается: ответ содержит `"type":"text"` и текст `Tool echo: проверка`.

### Проверка 2. Получение списка товаров

```
curl -X POST http://localhost:4000/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -d '{"jsonrpc":"2.0","method":"tools/call","params":{"name":"get-products","arguments":{}},"id":2}'
```

Смотрите, что придёт: список товаров или сообщение об ошибке. Запишите результат дословно.

### Проверка 3. Товар по идентификатору

```
curl -X POST http://localhost:4000/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -d '{"jsonrpc":"2.0","method":"tools/call","params":{"name":"get-product","arguments":{"productId":"p1"}},"id":3}'
```

### Проверка 4. Несуществующий товар — негативный сценарий

```
curl -X POST http://localhost:4000/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -d '{"jsonrpc":"2.0","method":"tools/call","params":{"name":"get-product","arguments":{"productId":"p99"}},"id":4}'
```

Сравните ответ с проверкой 3. Понятно ли из сообщения, что товар не найден?

### Проверка 5. Создание товара

```
curl -X POST http://localhost:4000/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -d '{"jsonrpc":"2.0","method":"tools/call","params":{"name":"add-product","arguments":{"product":{"name":"Кружка","price":500}}},"id":5}'
```

### Проверка 6. Создание без обязательного поля — негативный сценарий

```
curl -X POST http://localhost:4000/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -d '{"jsonrpc":"2.0","method":"tools/call","params":{"name":"add-product","arguments":{"product":{"name":"Без цены"}}},"id":6}'
```

Поле `price` обязательное. Ожидается ошибка валидации.

### Проверка 7. Удаление товара

```
curl -X POST http://localhost:4000/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -d '{"jsonrpc":"2.0","method":"tools/call","params":{"name":"delete-product","arguments":{"productId":"p1"}},"id":7}'
```

Теперь проверьте, что на самом деле произошло с товаром. Через MCP-сервер это не выйдет: `get-products` падает с ошибкой протокола. Спросите напрямую у заглушки:

```
curl -i -X DELETE http://localhost:4001/products/p1
```

Ключ `-i` покажет код ответа. Сравните его с тем, что сказал инструмент на предыдущем шаге.

### Проверка 8. Несуществующий метод

```
curl -X POST http://localhost:4000/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -d '{"jsonrpc":"2.0","method":"mcp.list_capabilities","params":{},"id":8}'
```

Этот метод вызывает скрипт `get_capabilities.ts`, приложенный к проекту.

### Проверка 9. Запрещённый метод HTTP

```
curl -i http://localhost:4000/mcp
```

Ключ `-i` показывает заголовки ответа, включая код. Без `-X POST` запрос уйдёт методом GET.

### Проверка 10. Поведение при недоступном API

Перейдите в **первое** окно (где заглушка), нажмите **Ctrl + C** — заглушка остановится.

Вернитесь в третье окно и повторите проверку 2. Сравните ответ с тем, что был при работающей заглушке.

Чтобы запустить заглушку обратно: в первом окне нажмите стрелку вверх и Enter.

## Часть 6. Завершение

Остановить программы: в первом и втором окне нажать **Ctrl + C**.

Окна можно закрыть, **Cmd + W**.

---

## Что фиксировать по ходу

На каждую проверку записывайте:

1. Номер и название проверки.
2. Команду, которую отправили.
3. Ответ дословно — копируйте целиком, не пересказывайте.
4. Совпал ли результат с ожидаемым.

Расхождения — материал для баг-репортов. Форма репорта в [шаблонах](../templates/bug-report.md), примеры оформления — в проекте [rusau-learn](../rusau-learn).

Отдельно записывайте версию Node (`node -v`) и дату прогона: без них репорт неполный.

## Если что-то пошло не так

**`command not found: node`** — Node не установлен, см. шаг 1.

**`command not found: npm`** — то же самое, npm ставится вместе с Node.

**`Cannot find module '.../stub-api.js'`** — вы не в папке проекта. Выполните `ls` и проверьте, есть ли файл в списке.

**`no such file or directory: package.json`** — вы не в той папке. Выполните `ls` и проверьте; при необходимости повторите шаг 2.

**`EADDRINUSE: address already in use :::4000`** — порт занят предыдущим запуском. Найдите окно терминала, где сервер ещё работает, и нажмите Ctrl + C. Если такого окна нет, выполните `lsof -ti:4000 | xargs kill` — эта команда остановит программу, занявшую порт.

**Ответ пустой, курсор вернулся сразу** — сервер не запущен. Проверьте второе окно: там должна быть строка про listening on port 4000.

**`curl: (7) Failed to connect`** — то же самое, сервер не запущен или запущен на другом порту.

**В ответе `Method not allowed`** — забыли `-X POST` в команде.

**Команда не выполняется, терминал ждёт продолжения** — скорее всего, не закрыта кавычка. Нажмите **Ctrl + C** и наберите команду заново.
