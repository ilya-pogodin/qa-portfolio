Основание: openapi.yaml, [systems-analysis/zooticket](https://github.com/ilya-pogodin/data-analytics-portfolio/tree/main/systems-analysis/zooticket)

## Что тестируем

Четыре метода платёжного API:

| Метод | Назначение |
|---|---|
| `POST /payments` | создание платежа |
| `GET /payments/{id}` | получение статуса |
| `POST /payments/{id}/refund` | возврат |
| `POST /webhooks/payment` | приём уведомления от платёжной системы |

## Что не тестируем и почему

- Внутренняя логика платёжного провайдера — вне зоны ответственности, проверяется только корректность интеграции.
- Нагрузка и производительность — отдельная задача, требует стенда и инструментов нагрузочного тестирования.
- Безопасность в объёме пентеста — проверяется только авторизация и подпись webhook на уровне функциональных сценариев.
- Интерфейс покупки — покрыт отдельным чек-листом.

## Виды тестирования

Функциональное (позитивные и негативные сценарии), тестирование на основе состояний (жизненный цикл платежа и билета), статическое тестирование спецификации.

## Техники тест-дизайна

Эквивалентное разбиение — для сумм, валют, статусов. Граничные значения — после того, как в спецификации появятся ограничения на `amount`. Таблица решений — для комбинаций «ключ идемпотентности × тело запроса». Переходы состояний — для статусов платежа и билета.

## Критерий входа

Сборка развёрнута на тестовом стенде, Swagger доступен и соответствует версии, получен тестовый токен, smoke-чек-лист пройден.

## Критерий выхода

Все тест-кейсы из [test-cases](../test-cases) выполнены, блокирующих и критичных дефектов нет, оставшиеся дефекты зафиксированы и согласованы, дефекты требований направлены аналитику.

## Риски

Часть тест-кейсов заблокирована из-за неопределённости в требованиях — см. [DEF-001](../defect-reports/DEF-001-idempotency-409.md) и [DEF-003](../defect-reports/DEF-003-refund-rules.md). До получения ответов ожидаемый результат по этим сценариям зафиксировать нельзя, и их выполнение не может служить подтверждением качества.

Сценарий одновременной валидации одного QR на двух турникетах на текущем стенде не воспроизводится.
