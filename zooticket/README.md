# ZooTicket — проектирование тестов по спецификации

Система онлайн-продажи билетов в зоопарк. Учебный проект курса «Системный аналитик» (Aston).

Исходные материалы проекта — требования, UML-диаграммы, кликабельный прототип и спецификация REST API в формате OpenAPI 3.0 — лежат в [отдельном репозитории](https://github.com/ilya-pogodin/data-analytics-portfolio/tree/main/systems-analysis/zooticket). Здесь собрано то, что строится поверх спецификации.

| Папка | Что внутри |
|---|---|
| [test-cases](test-cases) | 32 тест-кейса: создание платежа, возврат, переходы состояний билета |
| [defect-reports](defect-reports) | 4 дефекта требований, найденных статическим тестированием спецификации |
| [checklists](checklists) | smoke-проверка API и чек-лист покупки билета через сайт |
| [api-testing](api-testing) | план тестирования, матрица покрытия, коллекция Postman |

## С чего начать чтение

Сначала [дефекты требований](defect-reports) — они показывают, что можно найти в документе до того, как написана строчка кода. Затем [тест-кейсы](test-cases): часть из них помечена как заблокированные именно из-за этих дефектов.

## Особенность проекта

Работающей системы нет — проект существует как документация. Поэтому здесь нет баг-репортов в обычном смысле: находки получены статическим тестированием, то есть разбором спецификации на противоречия и пробелы. Выдуманные шаги воспроизведения в портфолио не кладу.

Находки по работающему приложению — в проекте [rusau-learn](../rusau-learn).
